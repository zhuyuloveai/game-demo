# 小厨合合 庄园扩展与六周更新计划

日期：2026-10-16

状态：设计稿，供分期实现与试玩评审。本文的新增玩法尚未上线；数量、价格、时长均为拟定初值，每期验收后调整。六周表示六个更新批次，不构成固定工期或留存效果保证。

## 1. 定位与参考取舍

把现有厨房扩展成一个可以逐步建成的美食庄园：田地与农牧提供食材，原有合成棋盘负责备料与料理，订单提供建设星星，餐车提供短局经营体验。玩家始终能知道“为了什么准备这道菜，以及完成后庄园会有什么变化”。

下表的事实来自官方介绍；取舍是本项目的设计建议，不代表对方全部玩法，也不使用未经验证的商业或留存数据。

## 2. 庄园地图与完整经营循环

### 地图和视觉

从现有“小店”入口进入可逐区展开的 2.5D 庄园地图。中央是别墅，左侧为田地与未来果园，右侧为鸡舍、牛棚等农牧区域，下方连接庭院餐桌与餐车出发点。道路、围墙和远景预留扩展位置，首期采用固定建筑节点，之后按验证结果增加区域。

保留现有暖瓷白、石墨文字和柿橙强调色，沿用物品美术及呼吸、点击、合成反馈。原 7×7 棋盘的布局和操作保持一致。地图用建筑轮廓、地面和角色形成层次，待解锁位置明确标注条件，避免把装饰画成可点击功能。

原厨房从第一期即可进入。旧装修、设备和配方进度对应别墅内已有厨房，不重新收取星星；第四期扩展备餐间、设备使用与菜单能力。第一期的田地位置仅作为后续区域预告，不提前实现种植。

### 同一条供给链

1. 完成原厨房订单取得星星，解锁庄园永久节点。
2. 田地与农牧提供确定品类的收成，进入备料区，玩家按需领取到棋盘。
3. 选择菜单，在棋盘上合成原料；使用保留的厨具加工成菜。
4. 交普通订单推进建设，或把食材打包为餐车备货。
5. 餐车营业取得金币与熟客进度，投入设备、装饰和下一套菜单。

原有 11 条普通合成链保留。新农牧链采用“同一种食材 → 整篮 → 备料”的三阶关系，例如小麦、整篮小麦、备好的面粉，避免一种作物合着合着变成无关作物。与旧链重叠时，通过标明数量的配方或转换入口衔接，不重命名、替换旧玩家物品。每个任务组先控制在 2–3 条活跃原料链，工具单独保护；其余来源可留在备料区。

备料区保存已收获物品，成熟后保留，领取前展示数量和需要的空格。收成不自动落到棋盘，不挤掉现有物品。原采购篮继续提供基础来源，田地和农牧增加定向供给能力；不会出现“等这块田成熟才允许完成唯一主线”的情况。鸡提供蛋、牛提供奶；不加入屠宰机制。第五期烤肉由采购铺供应，也支持蔬菜卷路线。

### 资源职责

| 资源 | 用途 | 约束 |
| --- | --- | --- |
| 星星 | 永久解锁别墅区域、田地、农牧与关键设施 | 保留现有余额；日常种植、营业不再重复付星星。 |
| 金币 | 设备升级、装饰、仓库与备货选择 | 基础食材保持可恢复来源，零金币不会阻断主线。 |
| 体力 | 棋盘上的主动生产 | 进入庄园、收获、装饰和餐车营业不重复扣体力；不增加第二体力条。 |
| 熟客进度 | 记录关系、偏好和菜单故事 | 是累计进度，不作为第四种消耗货币。 |

首章可用 12–18 星、后续章节 18–30 星作试算起点，单节点约 2–6 星。以上为待测预算，需结合真实订单成本与老玩家余额调整，不能由星价推算出“一定够玩一周”。老玩家存星正常有效；关键新功能可要求完成一次实际体验，如首次备料，不要求重复刷大量旧订单。

### 餐车营业边界

默认轻松模式，玩家主动开始一场约 60–120 秒的营业；允许暂停、切后台和稍后继续。挑战模式可选，挑战高分不作为主线门槛。夜市呈现夜景，开放时间不绑定现实晚上。

操作先收敛为取饼、加馅与酱、打包交付三组，设备升级改善操作便利。顾客要求控制在可读范围，练习模式不消耗备货，误操作不会让整车材料全部损失。

备货必须转成有来源记录的整数份数，例如一批材料提供 4 份馅料。尚未开局时撤销，按原批次退回原料；一旦开始营业，实际使用按份扣除，剩余份数保留在餐车库存，不能再退成重复的整份原料。重新开局优先使用库存。奖励与库存一次性结算，刷新、退出和重复点击不会重复发货。

## 3. 六个更新批次

每批次交付一个可以从进入玩到结算的闭环。以下数量都是内容预算初值，复用旧食材、配方与美术优先；第一、二期可以进入详细实现，其余在前一期验收后再确认。

| 批次 | 核心体验与拟定内容预算 | 延后项 | 验收与进入下一期条件 |
| --- | --- | --- | --- |
| W1 庄园开门 | 地图 4–5 个建设节点、10–14 个明确委托、2 个复用旧食材的配方；原厨房进出闭环；存档、防堵和经济审计 | 种植、动物、自由摆建筑、角色自由行走 | 旧档完整保留；能从做菜到花星建设再返回棋盘；满盘可恢复；无存档问题才进入 W2。 |
| W2 田地 | 3 块田、3 种作物、3–4 个跨旧链配方、4 个田园目标；定向收成与按需领取 | 枯萎、虫害、复杂肥力、浇水打卡、育种 | 收获满盘不丢；离线不重复发货；缺作物仍有推进路径。若主要增加收取负担，先改交互。 |
| W3 农牧 | 鸡舍与牛棚共用一种照料机制；蛋、奶各一条三阶链；4 个乳蛋料理或邻居委托 | 繁殖、疾病、动物交易、饲料生产树 | 漏登不惩罚；基础产出不依赖昂贵饲料；同时活跃链受控。若堵盘增加，暂停新菜扩展。 |
| W4 别墅备餐间 | 扩展厨房设备与菜单；2 个设备使用位、3 套主题菜单、4–6 个复用配方；庭院待客 | 全屋装修模拟、员工排班、家具数值套装 | 玩家能解释原料来源及工具保留规则；菜单无需同时生产所有菜系。若大量时间用于搬仓库，先修空间管理。 |
| W5 餐车首次营业 | 1 辆餐车、烤肉卷与蔬菜卷 2 条路线、3 组制作动作；每局先试 5–8 位顾客 | 多车队、雇员、连锁店、强制手速评分 | 备货与营业库存守恒；暂停恢复可靠；轻松模式能继续主线。若触控误操作、疲劳明显，先改操作。 |
| W6 主题夜市 | 复用餐车与庭院：3 组主题客群、2–3 种菜单组合、1 次熟客庆典；整合前五期能力 | 新货币、排行榜、多人交易、第三套独立小游戏 | 菜单选择确实改变备料或服务；避免只重复同一短局。用试玩结果决定之后内容，尽量不新增系统。 |

该顺序最大的风险是 W2、W3 连续增加来源，空间治理却拖到 W4。因此 W1 就要完成可选领取、工具消费保护和来源可用性判断；W2 自带备料区，W4 扩展它的用途。鸡与牛使用同一套机制，W6 以组合已有玩法为主。地图规模可以大，首轮实际可操作节点保持少而完整。

## 4. 一周的弹性内容节奏

目标是想玩时有进展，每天约 15–20 分钟可以舒服地完成一段；也可以集中在周末。每章暂按主线 60–90 分钟、选做 40–60 分钟准备内容，合计约 100–150 分钟。这是待试玩计时的假设，并非要求每天完成固定时长。

按七次游玩安排节奏，不要求连续七天：

| 游玩次数 | 本次目标 |
| --- | --- |
| 第 1 次 | 认识新区域，完成第一次建设，立即试到本章核心动作。 |
| 第 2 次 | 在两种来源或菜单间作选择，看到选择结果。 |
| 第 3 次 | 用新食材与旧厨具做一道新组合料理。 |
| 第 4 次 | 完成邻居或顾客特殊委托，场景再次变化。 |
| 第 5 次 | 正式待客、小庆典或首次营业，完成章节主线。 |
| 第 6–7 次 | 自选另一套菜单、装饰与熟客目标，也可以休息。 |

章节永久保留，错过更新不损失任务或奖励。无连续签到断档惩罚，无作物腐坏，无动物因漏登生病；建设付款完成后即时表现，不再添加现实时间施工门槛。农牧可有自然成熟表现，但基础来源、一次教学收获和可主动推进的目标保障当前游玩；不能把等倒计时当成每周内容。

每周以 4–6 次明显场景变化和不同目的的委托提供进展。普通随机订单承担补给，不能把“多交几十个相同料理”算作新内容。通关较快的玩家可以尝试另一菜单与外观，不用临时抬价延长章节。

## 5. 现有代码风险与技术分期

### 经济与空间基线

当前代码有 49 格棋盘、11 条普通链、7 类生产器和 10 道配方；体力上限 100，每 30 秒恢复 1。八段装修需要的星星为 3、5、7、9、11、13、15、18，合计 81 星。这些是试玩版本的事实，不是六周内容容量证明。

生产一次消耗 1 体力，二级产物概率为 `0.08 + 生产器等级 × 0.06`，一级为 14%，四级为 32%。普通物品出售价值为 `2^(等级-1)` 金币，所以把每次产物立即出售，一级的单次期望为 `0.86×1 + 0.14×2 = 1.14` 金币，四级为 1.32。商店又能用 30 金币换 30 体力，因此在能持续购买、出售的条件下存在正期望循环。随机结果、库存、冷却和操作时间会影响实际过程，不能解释为每轮稳赚或真实玩家收益。

订单收益、免费香草、礼盒、配方转换进一步影响经济。W1 先审计和记录各来源、消耗、最短推进成本，不突然削减老玩家余额或拉长体力恢复。新主线用永久节点与实际体验任务组织，金币不承担唯一进度门槛；任何调价另做明确的平衡变更。

此外，当前待领取区中的生产器也计入订单来源；每 3 单的礼盒会继续发生产器；订单会消耗普通厨具，而配方需要厨具留在台面。这些机制在扩展后会加重堵盘。应先增加可选领取、生产器收纳和工具保护；生成订单时确认来源确实可用，换单前可预览，避免新来源还没教学就要求生产。

### 实现顺序

- W1：整理节点与任务配置，增加庄园视图和存档保护；原引擎继续负责合成、订单与原厨房。完成防堵与经济审计。
- W2–W3：以共用产出、收取、容量规则接入田地和农牧；备料领取、满盘失败均保持原子性。
- W4：补充受保护设备与菜单依赖，食谱显式声明消耗材料和保留工具。
- W5：新增营业状态机，分别保存备货、营业中、暂停、待结算、已结算状态，使用唯一营业编号保证幂等。
- W6：以配置复用既有来源、菜单、顾客与奖励，先验证主题差异，避免继续扩大引擎范围。

### 不清档迁移与回滚

现有 `createGame()` 只接收 v1/v2，遇到其他版本会创建新游戏；旧代码也会在恢复后丢弃不认识的字段。直接增加字段或升级版本，并不自动意味着安全回滚。

迁移前保存原始存档和可导出备份，迁移成功校验后再写入新档；未知高版本应停止覆盖写入并提供恢复提示。完整保留棋盘物品及 ID、星星金币体力、仓库和待领队列、订单、设备、八段装修、配方与设置。新庄园、农牧和餐车使用独立版本的数据域，重复迁移不能重复发奖励。

保留已验证旧版本及其对应存档备份。回滚前记录新档，明确恢复旧备份可能失去回滚点之后的进度；优先采用兼容读取的修复版本，不能直接让旧代码覆盖新档。线上继续使用当前域名与端口。导出/导入属于首期能力；本地浏览器存档仍不等于云同步或跨设备账号。

## 6. 发布节奏、验收与后续选择

建议每批次采用“5+1+1”：约五天实现与自测，一天邀请 10–20 人试玩，一天修复、复核与发布。它是按团队实际可用时间安排容量的模板；核心验收未过就缩范围或延期，不强行按日历上线新系统。

试玩同时覆盖新手和有进度玩家，记录首次理解、卡住的位置、搬仓库次数、主动等待原因、营业误触、完成一段目标的实际时长。样本用于定性发现问题，不发布统计显著或留存提升结论。参与者能否在无解释时说清“我现在准备什么、做完能得到什么”，比凑齐内容数量更重要。

### W1 可直接执行的验收清单

- [ ] 提供 v1、v2、新档、八段装修完成档，以及满盘、满仓、大量待领队列样本；迁移前后逐项核对资产，重复迁移不重复发奖。
- [ ] 导出后可恢复；损坏档与未知高版本不会静默清档；至少演练一次发布和对应存档恢复路径。
- [ ] 从现“小店”进入庄园，打开已有厨房，完成一个配方与订单，花星建成一个节点，再返回原棋盘，整个循环可用。
- [ ] 实现 4–5 个明确建设节点及 2 个复用配方；未上线区域标注预告，点击不会进入空功能。
- [ ] 原配色、物品美术和 7×7 棋盘布局保持；320、375、390、430 宽度无横向溢出，触控目标可用。
- [ ] 满盘、零金币、零体力、唯一工具被选入订单、所需生产器在待领取区等情况均有可见恢复路径；物品与奖励不丢失。
- [ ] 已领取、建设、交单等操作连续点击或刷新不会重复扣费、发奖；工具保护与订单来源判定正确。
