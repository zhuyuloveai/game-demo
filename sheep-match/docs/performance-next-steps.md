# v12 后的性能工作边界（未实施）

v12 是已冻结的云端候选，不代表全部SLO达标。以下是依据真实 localStorage 和独立插桩副本的后续工作清单，不是已完成改动或已证明收益。

## 1. 世界几何驱动的可见性判定（中等范围，2个模块）

- 证据：v12 插桩 `motion.prepare` p99 29.7ms / max42ms，而 `motion.delight` p95 1.4ms、`motion.commit` p95 1.5ms。prepare读取动物及地图DOM矩形；此尾部耗时与可能的样式/布局刷新一致，但缺少DevTools trace，不能据此确认GPU或GC根因。
- 方案：向动物控制器提供来自 animalPlacement + camera + cached viewport 的可见性结果，避免在样式/DOM修改后同步读取布局；保留独立使用控制器的DOM fallback。
- 风险：动物晃动/镜像/遮挡、视口缩放与resize、拖动中可见边缘、图片留白会影响真实边界。必须保守overscan，不能为了数字把仍可见的动物停掉。
- 验收：视口四边进出、快速pan/zoom/resize、全围栏、12只动画上限、后台恢复与喂养序列；样式读取次数显著下降，且逐帧视觉无突然静止或消失。需要真正trace或独立分段复测归因。

## 2. 单实体/局部依赖的场景更新（中等至较大范围，world渲染专项）

- 证据：v12诊断收获后的完整map build约14.8ms、patch约18ms，合计约32.8ms；布局未修改的进入/退出已走fastpath，不能继续用“只改父class”解释收获成本。
- 方案：按实体id维护presentation descriptor及生成结果，收获/播种/喂养只刷新受影响对象及钱包/仓容/上下文必要小区域。clock-only仅更新变化倒计时，成熟阈值必须触发真实素材变化。
- 风险：库存改变也会影响仓满badge/禁用状态，建筑移动影响四邻域道路及遮挡，围栏由多层DOM组件组成；不能仅按实体对象引用判断dirty（store快照会克隆）。实际布局/成长蓝图/扩地/skin/透视保留完整fallback。
- 验收：无关精灵在单次收获中零属性/子节点变更；数量和存档结果一致；成熟不迟于下一可绘制帧；3×60秒及10分钟同负载，输入可见反馈和长任务一起验，不只选rAF p95。

## 3. 同步存档工作预算（高风险架构专项，不与本轮混合）

- 证据：15个真实浏览器localStorage tick诊断p50：候选完整验证3.3ms、回读完整验证4.9ms、envelope克隆/校验和2.1ms、emit含冻结/渲染5.3ms；总tick p50 19.5ms / p95 26.4ms。各分位不可直接相加推算整体；该插桩是诊断，不作最终性能验收。冲突读取p50约0.1ms，不应把问题简单归咎于磁盘I/O。
- 优先先完成1和2再复测，保留每笔CAS、写入后完整验证与逻辑时钟持久化，不能通过降低保存频率或删除校验凑达标。
- 若严格每帧应用工作≤10ms仍无法满足，Worker准备/校验需命令串行化和异步确认协议。Worker无法直接访问localStorage；主线程写入/读回后须等验证确认才发布成功，写入前重新CAS、writer lock贯穿在途commit，tick/action/import/close/takeover同队列，命令重试幂等，崩溃/超时按A/B规则恢复。
- 改IndexedDB是另一个存储迁移工程，不应与“把校验放Worker”混称。跨线程克隆和消息成本也可能抵消部分收益。

## 发布前仍需的外部证据

- 用户实际部署域名（当前IP地址证书错误；未绕过），确认部署build/缓存与运行包一致。
- Android/iOS基线设备、真实触摸、移动GPU与热降频；云rAF不是手机实呈帧率。
- 连续高频画面/视频检验零闪烁；单帧和DOM身份只能支持有限观察。
- 同状态、同GC口径保留堆与监听器/定时器泄漏验证；当前heap只是观测值。
- 冷暖启动及固定弱网、图片失败/解码等待路径；未测试项不能写为通过。
