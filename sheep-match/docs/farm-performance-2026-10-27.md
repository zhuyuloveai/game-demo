## 已定位的主要原因

1. **状态读取放大**：原 scene context 每访问一次 `state` 就调用深拷贝 `getState()`；渲染内部循环、几何/标题/动效解析又多次读取。阶段3一分钟产生 127,608 次额外深拷贝，包装计时累计 51.65 秒。该计时不是 CPU sampling profile，但直接测到了具体同步热路径。
2. **每秒销毁重建场景**：tick 无论是否只推进时间，都触发 `world.innerHTML`，全部实体/图片/动画节点重建；同时清掉森林缓存。阶段3一分钟 39 次世界和森林重建，原实体节点丢失。这提供周期性闪烁和动画重启的明确代码机制；mutation count 本身不等于视觉闪烁次数。
3. **拖动路径过重**：每个相机变换再次扫描动效节点、读取布局/更新样式；render 内还有重复刷新。新版手势期间只更新相机/必要的量化森林可见范围，结束后统一动效同步。
4. **隐藏层重复更新**：打开叠层页面后原场景仍订阅并重画；新版只由 host 订阅一次，冻结一份安全 presentation snapshot，inactive/inert 场景暂停刷新，返回时追上最新状态。
5. **相同存档反复校验**：每次冲突检查重新解析、校验两个完全相同的 A/B slot。新版按 slot 缓存最近的精确 raw 字符串及已校验不可变 envelope；仍每次读取 storage，raw 改变仍完整校验，写后仍读回验证。缓存仅两项。revision 不同先证明状态变化，revision 相同仍保留完整 canonical 比较。

## 修改与正确性保障

- keyed DOM patch 保留实体、图片、森林节点和动效自有属性；只更新变化属性/文字，不把绘制好的资源重新插入。
- 时钟推进只改倒计时，真实生长美术 key、成熟/施工阈值、肥料到期等变化仍触发绘制。
- 森林保护范围随实体位置/美术尺寸变化失效，连续操作不再重复克隆退场树或取消待执行清理。
- 动物控制器会检测实际 SVG image href，修复无关结构更新覆盖当前动画帧的情况。
- **没有**关闭动画/森林/成熟特效，没有减少动物数量，没有跳过持久化 tick、CAS、多窗口冲突检查或写后校验。
- 新模块纳入正式 runtime 打包白名单；本地打包验证通过（1000个运行文件），没有部署。
- 自动测试：较早轮次 **599/599** 通过；负责人报告v7最新轮次为 **618/618**（此前608/608）。这些是各自代码快照的功能测试，不能绑定到旧缓存after性能样本，也不是后续candidate-v8或最终提交的预先验收；最终代码仍须重新核验。独立审阅覆盖缓存安全、时钟/持久化、冻结快照、叠层刷新、成长阈值、退场清理与动画帧恢复。部分视觉签名测试执行生产代码片段，不冒充浏览器 E2E。

## 方法、仪器开销与复现

测试页：`sheep-match/tests/farm-performance.html`（仅测试文件，不打入正式运行包）。通过普通静态服务器打开；不要在玩家正式origin运行。

- 正式候选测量必须让测试页的 `base` 指向独立、冻结、带版本号的候选目录，记录 `moduleBase` 和对应 `sourceHashes`/哈希清单。仅更改 `build=after` 标签或重新读取磁盘哈希不能保证浏览器模块更新。
- 基线：同测试页通过相对 `base` 指向独立3046927 worktree的 `sheep-match/`，`build=before`。base限制同源相对路径。
- `stage=1/2/3/pens/max`；60s idle、60s pan、60s mixed和10min soak由按钮启动。
- localStorage只读写/重置 `farm-perf-qa:a`、`:b`、`:active`，从不调用 `localStorage.clear()`，不触及正式存档键。`locks:null`刻意隔离单实例性能，不代表实际Web Locks与多标签体验验收；多窗口语义由存档回归测试覆盖。
- 通过PerformanceObserver长任务、rAF间隔、MutationObserver子节点变化（旧字段worldRebuilds/forestRebuilds不是稳定的全层重建计数）、getState包装计数/计时、真实store tick耗时、每秒heap观测及DOM动作确认记录。原始结果见 `performance-evidence/2026-10-27/`。
