# 农场性能 SLA / 项目 SLO 验收方案

更新：2026-10-27。本文定义目标与方法，不记录或宣称任何实测通过结果。实际结果须关联提交 SHA、环境和原始证据。

这是本项目拟定的性能 SLO（服务目标）及发布验收门槛，不是 Hay Day、Township 等竞品公开 SLA，也不保证所有手机达到同一帧率。权威来源支持帧预算与测量方法；下面的百分位、容差、加载和内存回归门槛由项目提出。

## 1. 分档目标

固定 60Hz 显示条件，前台可见、关键资产就绪后采样。每个代表场景连续 60 秒，至少重复 3 次；分别报告每次结果，不以合并平均值隐藏最差轮次。设备分档最终必须绑定实际机型、系统和浏览器版本。

| 指标 | 高档目标 | 基线手机目标 | 低档降级目标 |
| --- | --- | --- | --- |
| 连续运动渲染目标 | 60fps | 60fps | 稳定 30fps |
| 目标帧周期 | 16.7ms | 16.7ms | 33.3ms |
| 应用每帧工作预算 | ≤10ms | ≤10ms | ≤20ms |
| rAF 间隔 p95 | ≤20ms | ≤20ms | ≤36ms |
| rAF 间隔 p99 | ≤34ms | ≤50ms | ≤67ms |
| rAF 间隔超过目标周期 1.5 倍的比例 | ≤1%（>25ms） | ≤3%（>25ms） | ≤3%（>50ms） |
| 输入到有意义可见反馈 p95 | ≤100ms | ≤100ms | ≤150ms |
| 输入到有意义可见反馈 p99 | ≤200ms | ≤200ms | ≤200ms |
| 稳态 >50ms 主线程长任务 | 0 次/分钟 | ≤1 次/分钟 | ≤2 次/分钟 |
| 稳态 >100ms 主线程长任务 | 0 | 0 | 0 |

低档目标仅在明确启用并验证稳定 30fps 策略时适用，不能把无法达到 60fps 的波动帧率事后改称降级通过。初始化和切换的长任务单列报告，不混入或默默删掉。

### 指标不能混淆

- **rAF 间隔是回调调度代理，不等于屏幕实际 presentation 帧率。** 浏览器仍可能在 Paint、Raster、Composite 阶段丢帧。用 Performance 帧轨迹、截图时间线和必要的真机视频交叉核验；仅代理过线标记为“云端代理通过”。
- **输入处理耗时、输入到 next-rAF 不是输入到可见反馈。** rAF 在绘制前回调；处理函数很快也可能尚未显示反馈。以 Event Timing（可用时）结合 trace/filmstrip确认下一次绘制包含选中、按钮态或操作结果。自定义 next-rAF 结果须明确标记代理，不能独自完成输入 SLA 验收。
- **12fps 精灵姿态不是整页 12fps。** 可以每约 83ms 换一次动物姿态，位移、拖拽及相机仍应平滑更新。逻辑时间、姿态采样、位移和浏览器渲染应分别计量；按时间推进逻辑，不能依赖“每帧一次”的假设。
- p95/p99 指样本延迟的百分位；长任务以主线程任务 >50ms 计数。背景标签页节流不计入前台流畅度，但切后台恢复必须另测。没有适用 API 时标记未测，不能写 0。

## 2. 场景和输入覆盖

使用隔离 QA 存档，不修改真实玩家存档。锁定种子、状态、相机、视口、DPR与缓存状态，优化前后使用相同脚本：

1. 三个成长阶段分别测；最繁忙场景覆盖 48 块田、15 棵树及满载围栏，并记录实际对象数。另设 24 只鸡的姿态动画场景，不能替代完整繁荣农场。
2. 待机动画、连续平移、放大缩小、连续点收/播种/喂养、开关仓库和商店、布局模式进入/退出、离开农场并返回。
3. 交互阶段每种代表操作至少 30 次，记录失败/丢失输入；不能仅测空闲页面的帧率。耗材不足等情况应可重复重置，保持前后工作量一致。
4. 首次进入、冷缓存、已缓存、图片加载失败/慢加载、方向或视口改变、后台恢复单独验证。

## 3. 零闪烁是独立发布门槛

必须检查连续动画、收获、升级、弹窗、切换与缩放中的空白精灵、整层闪白、错误遮挡、锚点跳变和未解码图片替换。**CLS=0、rAF 达标、图片 complete=true 均不能证明没有闪烁。**

- 动态替换资源前下载并成功 `decode()`，失败时保留旧图或明确占位，不先清空可见图；固定尺寸与锚点。解码策略是防护，不是无闪烁实测结论。
- 使用局部 ROI 截图时间线/视频，排除预期的动画、提示和光效后检查异常空白帧与瞬时消失；保留异常前后帧及对应操作。低频截图可能漏掉一帧闪烁，需高频证据或人工真机复核。
- 视觉检查未做或采样不足，写“未完成视觉验收”，不可用自动性能测试代替。

## 4. 加载目标

建议固定网络 10Mbps 下行、1Mbps 上行、100ms RTT，明确使用网络节流工具及单位。冷缓存 5 次、暖缓存 5 次分开记录原始值及 p75；这只是小样本实验，不等同真实用户总体分位数。

- 项目目标：1 秒内出现有反馈的加载界面；冷启动可玩 p75≤5秒，暖启动≤2秒。
- “可玩”指关键场景资源已解码、输入处理已绑定、首次交互可成功，需专用 readiness 标记和交互验证，不等于 LCP。
- 官方 Core Web Vitals 参考：真实用户页面访问 p75 的 LCP≤2.5秒、INP≤200ms、CLS≤0.1，按移动/桌面分组。不能把本项目交互样本 p95 当成官方 INP，也不能以 CWV 替代游戏帧率。

## 5. 必须执行的 10 分钟稳定性发布门槛

每个拟声明支持的设备档在最繁忙场景进行至少 10 分钟前台 soak。持续循环平移、缩放、点收、弹窗、切换及返回，不能以 10 分钟待机替代。云端先跑相同场景作为回归门槛，真机另验。

- 无崩溃、未处理异常、丢失输入、黑屏、异常重载及存档损坏。
- 预热后第 2 分钟与第 10 分钟，在相同场景和相同 GC 口径比较保留 JS 堆，增长≤`max(5MiB, 第2分钟基线的10%)`；这是项目回归阈值，不是浏览器官方内存上限。
- DOM、监听器、定时器以及已退出页面的引用不持续增长；返回同一状态后应回到近似基线。记录对象保留原因，合理缓存须说明容量和上界。
- 相同工作负载下，最后 2 分钟帧间隔 p95 相比稳定后的前 2 分钟恶化≤10%。正式报告明确比较窗口，避免把初始化计入起始窗口。
- 强制 GC 仅用于分开的内存诊断，不在流畅度采样中不断触发。JS heap 不含全部图像解码、GPU纹理和进程内存；单看 heap 不足以声称无内存问题。记录可得的进程/资源峰值；不存在通用的“所有手机安全 MB 数”。
- 10 分钟未跑、缩短或中断必须标记未完成，不能以短测推断通过；真机仍须检查热降频和持续操作表现。

## 6. 云端结果的适用范围

记录提交 SHA、浏览器版本、操作系统、CPU、GPU/软件渲染器、headless/headful、启动 flags、视口、DPR、显示刷新条件、CPU/网络节流及缓存状态。使用同环境、同脚本对比优化前后；轻量指标与带截图的重型 trace 分开跑，注明采样开销。

1×/4×/6× CPU 节流是实验压力档，不是实际手机型号。云端可以建立调度、DOM变更、资源错误和回归证据，**不能标记“基线手机已通过”**，也不能证明 Safari 合成、真实触摸链路、移动 GPU、功耗或热降频已通过。真机缺失时写明“云端代理已测；Android/iOS 真机未验”。最终需代表性 Android Chrome 和 iOS Safari 真机，设备清单与支持范围同步记录。

报告对每项分别标记：通过 / 失败 / 未测 / 仅代理。提供原始数据、p50/p95/p99、长任务、加载/解码失败、内存曲线与关键视觉证据。帧率或输入指标缺少真实呈现证据、零闪烁视觉检查缺失、10分钟soak未完成时，不得声称完整性能发布门槛已通过。

## 7. 权威参考与适用边界

- [web.dev：Rendering performance](https://web.dev/articles/rendering-performance)：60Hz 帧周期约16.66ms，应用工作建议约10ms；渲染包含 JS、Style、Layout、Paint、Composite。
- [web.dev：Optimize long tasks](https://web.dev/articles/optimize-long-tasks)：主线程 >50ms 为长任务；拆分任务可改善响应，但不替代完整帧预算。
- [Unity：Best practices for profiling game performance](https://unity.com/how-to/best-practices-for-profiling-game-performance)：移动帧率需考虑功耗/温控与空闲预算，讨论30/60fps取舍。用于支持分档思路，不把 Unity 原生指标直接套成浏览器实测。
- [MDN：HTMLImageElement.decode()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode)：图片解码后再加入/替换有助于避免空图及绘制时解码等待。
- [Google：Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals) 与 [web.dev：INP](https://web.dev/articles/inp)：网页体验阈值及真实用户p75口径，不是游戏内部帧率 SLA。
- [Chrome：Fix memory problems](https://developer.chrome.com/docs/devtools/memory-problems)：区分泄漏、膨胀和频繁GC；不同设备没有统一的内存硬上限。
- [Chrome：Device Mode limitations](https://developer.chrome.com/docs/devtools/device-mode)：移动模拟只是近似，实际设备架构与表现必须真机验证。
